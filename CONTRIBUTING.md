# Contributing to Lattice

Lattice welcomes code, documentation, testing, operational experience, and careful technical criticism. Pseudonymous contributions are welcome.

## Start here

- Read the documentation in [`docs/`](./docs/).
- Use [GitHub Discussions](https://github.com/adalinxx/lattice-node/discussions) for questions and design exploration.
- Use [issues](https://github.com/adalinxx/lattice-node/issues) for reproducible bugs and scoped work.
- Report vulnerabilities through the private process in [SECURITY.md](./SECURITY.md), never through a public issue.

Before opening a large implementation, describe the problem and proposed boundary in a discussion or issue. Small correctness fixes and documentation improvements can go directly to a pull request.

## Pull requests

A useful pull request:

1. explains the user or protocol problem;
2. keeps unrelated changes separate;
3. adds tests for the behavior it changes;
4. documents security and compatibility implications;
5. records what was run to verify the change; and
6. contains no generated attribution, promotional signatures, or personal information that the contributor did not intend to publish.

Protocol and cryptographic changes need test vectors or independently checkable fixtures. User-interface changes should include keyboard, narrow-screen, failure-state, and accessibility coverage where applicable.

## Community record

Chat is useful for coordination, but decisions that affect behavior, security, or interoperability must be recorded in an issue, discussion, specification, or pull request that can be reviewed later.

By participating, you agree to the [Code of Conduct](./CODE_OF_CONDUCT.md).
